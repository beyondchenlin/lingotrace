## How to read identities and evidence

“Implementation source” identifies the editable application source snapshot. “Generated-release commit” identifies the Site's packaged runtime revision. Site version, build ID, source tree and runtime hashes provide additional independent identity. They must not be substituted for one another.

A GitHub import can project a source tree or recreate commits with new IDs. Preserve the original identities below and verify the resulting import map separately. The branch names in `PUBLISHED-VERSION-MAP.json` are proposed backup refs; that manifest alone does not prove remote refs exist.

The selected ancillary archive places each version's build receipt, runtime hashes, source manifest, publication receipt and HTTP identity under `published/vNN/`. An original build receipt can correctly say “not published” because it predates its companion publication receipt. Use the dated later receipt for the later publication fact, rather than rewriting either original.
