# Shared Studio responsive candidate

The v31 fixture page was rejected because it omitted the original motion and training features. This correction renders the same Studio component at /portrait-preview/, with responsive geometry enabled. There is one existing TrainingEngine, original IndexedDBTrainingRepository, PageInputGate, TransparentInputProjector, media nodes, SceneRecorder and Canvas surface. No new practice model, demo ledger, generic fixture scene, migration, microphone permission or scoring rules are introduced.

The desktop scene remains 1672×941. Portrait resolves to 430×1080 logical coordinates with a corresponding 860×2160 recording surface. Real goal/flow media/trend/subtitle/input/player layers are relocated, and the same layout resolves native controls, seek gestures and editor handles. Portrait input font, tracking, padding, caret/selection and scroll offset use the console scale. Editable layout preferences use a separate portrait key; original landscape preferences remain intact. Automatic narrow layout and explicit preview controls change geometry without remounting Studio or resetting input, clocks, media or the recorder. Resizing during a drag cancels that drag before switching coordinate spaces.

All existing tools remain reachable: media/camera/layout, subtitles/hints, submit/cue navigation, pause, review/replay, JSON/CSV, opt-in sound, canvas recording, recording library, screenshot and settings. Reference-art comparison keeps its original landscape geometry. The inherited legacy pace label issue remains documented separately; this layout batch does not redefine metrics.

Desktop rendering was independently compared against the exact prior renderer: 24 state/layout/size combinations produced byte-identical PNGs. The full primary regression suite passed 261 tests and media suite 52 tests; TypeScript and the Next static build passed. Scope review closed two issues: saved-layout reset overlay alignment and a distinct portrait side-by-side geometry. Program images showing text selection alone are not input-state evidence; additional frames drove the existing engine/projector with committed input and submission.

Publication uses scripts/assemble-portrait-preview.mjs rather than the normal whole-site assembly. It replaces only the rejected portrait route and adds missing content-hashed Next dependencies. All pre-existing resources outside that route are compared byte-for-byte; the existing /studio and /story/cafe remain unchanged. Uncommitted development Practice files live in a different untouched checkout and are excluded.

Actual browser input→live, motion, storage/reload/export and recording checks follow candidate deployment. Program pixels do not prove browser motion or physical phone behavior. Actual phone viewport/rotation/OS keyboard and recording across orientation changes require explicit evidence; no such pass is claimed here.
