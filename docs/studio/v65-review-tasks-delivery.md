# v65 candidate — explicit local review dates and real retests

Baseline: v64 / `0b5b8bac3c47e24f29c253224118f10dac4f0b82`.
Status: implementation candidate. Independent frozen-code review and normal HTTPS acceptance are required before this is a release. No v65 deployment is implied by this document.

## User loop
The submitted sentence row in the existing round-review panel offers an explicit date/time and IANA zone. It saves a stable task from the actual durable Training submit/judgment. The existing settings panel opens the local task list. A user can reload, cancel, explicitly choose a date to restore or reschedule, export evidence, or explicitly end the current round and open a fixed-reference retest. Before that retest the user selects its next due date. The first eligible, successfully committed real result advances this occurrence once to exactly that date. Incorrect and assisted results remain their actual Training results; no mastery/pass threshold or interval policy is invented.

Task creation, list reads, planning, cancellation and rescheduling never invoke the scorer. The normal `TrainingEngine.submit` remains the only answer/result source. Actual linked result summaries are read from already validated historical words/errors/accuracy at read time, not copied to a second score store.

## Four independent design conditions closed in implementation
1. **Occurrence identity:** `review-task-storage.ts` keeps the won occurrence, result relation and session binding, atomically creates the successor and updates the task revision/current pointer. A successor has no inferred following date. Old sessions never follow it. Cancel/reschedule/restore use CAS, and restore requires explicit due.
2. **Exact evidence and privacy:** `review-task-source.ts` locates actual engine request/judgment IDs. `review-tasks.ts` validates saved full or recorded partial request-before-result/answer/target/words relationships. `repository.ts` adds narrowly namespaced same-database transactions with existing epoch/control/permit fences and local capability revocation. OFF clears the host's volatile pending association map; ON/refresh never scans old answers for missed progress. Full/partial facts, grading and old exports are unchanged.
3. **Safe startup:** `Studio.startReviewTask` holds the transition lock through target verification, instance preparation, old-round flush and final adjacent boundary assertion, synchronous reset, new permission admission, persisted new session and exact binding. A post-reset failure remains visibly blocked until the explicit ordinary-practice choice. Fresh bindings allow only non-answer preparation facts; partial uses freeze/time/observation metadata and refuses inputs, hints, composition and navigation. Existing old `beginNewRound` behavior is not globally rewritten.
4. **Hidden reference and strict media:** the retest has its own startup, never the auto-revealing corrected-version confirmation. The target cue can differ from the edited cue. It validates immutable material/digest/ancestor library plus verified lease identity, actual SHA and duration. It never falls back to another URL or a guessed 72 seconds. Every acquisition, metadata wait and verification digest has cancellation/source ownership; failed and stale operations release only their resources. Explicit reveal uses the existing ordinary reveal fact, with no new surface enum.

## Deliberately remaining
This is F13's explicit-date local task/retest sub-loop, not all F13. Automatic intervals, success/failure/mastery policies, word-level task generation, correction-adoption/split-merge migration and notifications remain outside this release. Reference adoption never means auto-latest. Only the existing original cafe media and verified immutable local corrections are supported. Missing evidence/reference/media is explicitly unavailable; partial assistance and complete provenance remain unknown. OFF/partial refresh restores the task library, not the old practice or writer permit. No new microphone/camera access, audio assessment, story, AI service or cross-device feature is added.

Main scene geometry, CSS, renderers, anchor/standby animation and grading source are unchanged. v48-and-later appearance still has no explicit user visual acceptance. Earlier device/background/recording evidence boundaries remain separate from this candidate.

## Independent candidate review correction
A normal partial-history sequence exposed a real pre-release queue issue in program-level host tests: type two answers, undo to a prior answer (correctly redacted), submit, clear, then type and submit a wholly recorded new answer. The ineligible first source used to remain at the volatile association queue head and block the second valid attempt. The host now treats only a proved `invalid-source` as terminal for that individual candidate: no result pointer, answer copy or winner is stored for it, its redacted fact is untouched, and subsequent independently recorded attempts continue. Storage/quota and permission failures retain the honest explicit retry path; OFF still clears all candidate authority. Sequential, same-drain, quota retry and OFF→ON cases have retained red/green tests. This was not claimed as an observed HTTPS incident.

The production packaging helper now synchronizes both `/studio/` and `/portrait-preview/`, which share the same Studio source. Both final entrypoints must reference the same newly built shared Studio chunk; old immutable hashed assets can remain for already-open clients. No additional visual layout or route feature is introduced.
