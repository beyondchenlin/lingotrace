# 详细需求增补：竖屏画面中断恢复（候选，2026-10-11）

与同目录 PRD-total.md 配套。正式 v82 的已有 135 份需求及 10 份附录全部保留；此次仅追加本总纲/详细增补。

## 可验证的缺陷与限制
旧 Studio 的 draw 在函数尾调用 requestAnimationFrame。测试执行实际源码提取出的 RAF setup，注入一个帧异常后，旧版待运行帧数为 0；候选为 1，下一帧成功后持续绘制。该测试证明生命周期缺陷，不证明手机发生了同一种注入异常。

对真实渲染器的 320 个 unavailable-NPS/hello/竖屏尺寸/键盘开关/时钟组合未发现异常。对 896 个竖横屏、viewport、键盘位置和 HUD 模式组合迭代测量均收敛，最大测试背板为 8,110,080 像素；此结果未发现无限尺寸反馈，不等于真实设备资源验收。未加猜测性的尺寸上限。

## 实现约束
- frame-loop 控制器捕获帧异常，先通知录制截止，再通过 Canvas width 自赋值重置整个绘图状态栈，最多安排一次自动重试。
- 连续第二次失败停止排帧；手动重试重新建立有限恢复窗口。卸载取消待帧，不能在旧组件上重启。
- 持续失败使用原生 modal dialog，含明确错误与 Retry display；键盘焦点由原生模态机制约束并在关闭后恢复。取消事件不能悄悄隐藏仍失败的画面状态。
- sceneFailure 仅为显示状态，不写入练习快照。不暴露异常堆栈、草稿或参考内容。
- 录制 cutoff 必须在清空画布前同步发生；已接受、排队和最终片段排空后才标为 SCENE_RENDER_INTERRUPTED/incomplete。不得自动继续录制。
- 指针点击 Canvas 标记 pointerFocused；键盘输入/失焦解除标记。键盘 focus-visible 样式仍生效。
- 当前媒体错误入口要求当前 visual ready=false 且当前媒体已进入失败状态；generic courseError 中的选材入场失败不能污染原媒体画面。
- 新请求的 loading 状态不能沿用旧 error；过期请求不得覆盖当前文案、来源、准备状态。保留所有 token/所有权/SHA 守卫。

## 回归与发布要求
覆盖实际 RAF 提取红绿、有限重试与手动恢复、嵌套 clip/save 状态重置、草稿保持、录制 final chunks 保留及不完整标记、旧源/新选材失败归属、原型媒体失败文案、竖屏尺寸收敛、现有输入/Hidden/Below/HUD/媒体/录制测试。

构建与发布仍是独立门槛。当前手机特定触发原因、Android 原生软键盘、实际录制设备和 NPS body 失败均未获此次候选的真实设备验证。正式浏览器 error9 阻止点击前验收，因此没有键盘浏览器通过或失败的结论。
