# v27 continuity and input-trace correction

Baseline is v26 source 978219fc4c4beae657424f13c026719ddf605c95. This candidate changes motion and chart drawing; stage layout, controls, recorder routing and training facts remain unchanged.

## Source diagnosis, not browser FPS

Independent calculations found C1-continuous energy joins and wrap, but the squared attack compressed its 10–90% rise into 63–78 ms. The renderer's strict `> 33.333ms` gate discarded its remainder. A modeled sequence of approximately 60 Hz callbacks produced alternating 33/50 ms paints, approximately 24 Hz. Uniform near-threshold intervals could produce 20 or 30 Hz. This is deterministic source evidence, not an actual browser frame-rate measurement.

The ring used a rounded word readout as its geometry: each word was a 15-degree step. A modeled attack could jump 120 degrees over 33 ms. Trend samples moved their sampling phase on every frame; 75 ms samples varied an unchanged historical peak by approximately 1.6–2.2 pixels. The 30-second viewport compressed each fast rise into less than one horizontal pixel. Left-side history was generated by a bipolar ECG-like wave kernel, and its entire height was rescaled by present energy. React state was not responsible for advancing those frames; its contribution to device performance was not established.

## Limited correction

- Paint on each available RAF callback. Capture performance.now once in that callback and use the same clock for input observations and painting; do not mix the callback's older start timestamp with subscription observations. Real metric bins remain one-second samples. No target-FPS success is claimed without browser measurement.
- Keep the energy's maximum unchanged. Spread attack over 390–460 ms using the full smootherstep, with a meaningful rise of at least 190 ms. Damped decay and low dwell remain. Continuous goalFraction draws the standby ring; rounded digits no longer move geometry.
- Standby trend uses immutable 40 ms timestamps, a causal five-tap display smoothing kernel and a 12-second window. Historical geometry moves through subpixel translation. Sparse endpoint markers replace dense nodes. This remains labeled synthetic standby data and never enters training.
- Live trend retains actual one-second values and a 30-second window. Monotone cubic drawing preserves exact endpoints and local bounds; existing null/missing intervals split paths. No new measurement or interpolated fact is stored.
- Input flow uses positive event bars rather than an audio or ECG waveform. Each bar has a fixed height from that event's added graphemes and an age-based position. New input can emphasize its own bar, never expand past bars. Paste/deletion do not generate positive-input bars. The count still includes changed committed events according to the existing contract. No microphone or audio samples are used.
- Optional v26 audio remains opt-in, destination-only and excluded from the recorder mix. It follows the revised shared energy and existing visibility/reduced-motion/real-input gates.

## Evidence and remaining acceptance

71 focused tests, all 239 primary tests, 52 media tests, TypeScript and the static build pass. Independent source review found no blocking issue; the trace-window comment was corrected. A ten-second 1280×720 program clip at an explicit 60 Hz clock and phase frames at 1672×941/1920×1080 were generated from the actual renderer. The clip is silent and is not a browser recording or a measured 60 FPS claim.

Independent source review and full gates precede candidate deployment. Actual-browser comparison must establish cadence/frame times, visual continuity during a complete cycle, old-draft reopen/first real input, measured trend gaps, reduced motion and a synthetic recording. User perception of the redesigned traces is not inferred from one still image. The existing v26 remains published until its baseline timing evidence is fixed.
